# Braching Chat 系统深度分析 Prompt

## 📋 项目概览

**项目名称**: 智绘·无限画Canvas（Braching Chat）

**核心定位**: AI驱动的商业模型实时协作分析平台

**技术堆栈**:
- 前端: Next.js 14 + React 18 + ReactFlow + Zustand
- 后端: LangGraph + LangChain + Node.js
- 数据: PostgreSQL + Supabase
- AI: OpenAI API（结构化输出）

---

## 🎯 系统架构

### 核心智能体系统（6个Agent）
```
用户输入 → Router Agent（意图分类）
         ↓
    ┌────┴────┐
    ↓         ↓
[generate_bmc] [detect_conflicts]
    ↓              ↓
    ├→ Market Agent    Critic Agent
    ├→ Product Agent   (冲突检测)
    ├→ Finance Agent
    ↓
Orchestrator Agent
(聚合+连接)
    ↓
最终输出(Canvas)
```

### 数据模型（CC-BMC 9维度）
1. **客户维度**: 客户细分 / 渠道通路 / 客户关系
2. **价值维度**: 价值主张 / 收入来源 / 关键业务
3. **支撑维度**: 核心资源 / 重要合作 / 成本结构

### 前端交互流（当前）
1. 用户输入种子问题
2. LangGraph异步生成节点
3. WebSocket推送增量更新
4. ReactFlow实时渲染Canvas
5. 右侧Chat面板显示对话

## 💼 商业现状分析

### ✅ 已有优势
- **技术完整性**: 全栈实现，编译通过，可部署
- **AI整合深度**: 6个专门化Agent，结构化输出，prompt精心设计
- **可视化能力**: ReactFlow Canvas呈现复杂关系，节点丰富
- **实时性**: WebSocket流式推送，用户可实时看到AI思考过程

### ❌ 商业价值缺口

| 维度 | 当前状态 | 商业需求 | 差距 |
|------|--------|---------|------|
| **协作** | 单人操作 | 团队共同编辑 | 🔴 无权限系统 |
| **持久化** | 基础会话存储 | 版本控制/回滚 | 🔴 无版本管理 |
| **输出** | 仅屏幕显示 | 多格式导出 | 🔴 无导出功能 |
| **复用** | 每次重新生成 | 模板库/组件库 | 🔴 无复用机制 |
| **扩展** | Canvas只读 | 用户可编辑 | 🔴 无编辑器 |
| **分享** | 内部工具 | 分享链接预览 | 🔴 无分享功能 |

### 🎭 竞争格局
- **Figma/Miro**: 协作+无限Canvas，但无AI
- **ChatGPT/Claude**: AI强大，但无可视化
- **Lucidchart**: 商业图表工具，但AI弱
- **你**: AI + Canvas，但缺协作和输出

## 🤔 核心问题诊断

**不够商业的真实原因**：

1. **缺少商业闭环**
   - 现在: 用户问题 → AI分析 → 看结果 → 然后呢？
   - 缺少: 保存、分享、迭代、导出的完整流程

2. **团队协作缺失**
   - 无法邀请同事看同一个Canvas
   - 无法互相评论讨论
   - 无法追踪谁做了什么改动

3. **知识未被积累**
   - 每个分析结果是一次性的
   - 无法重用之前的分析框架
   - 团队学习曲线陡峭

4. **用户掌控度低**
   - AI生成的内容用户不能改
   - 没有撤销/重做机制
   - 被"智能生成"束缚，不自由

## 🏗️ 三条可能的前端重设计路线

### 路线 A: Notion 式内容管理平台
**目标**: 个人/团队的商业笔记系统

**关键特性**:
- 块级编辑（节点可编辑）
- 权限分享（公开/私密/受邀）
- 评论讨论（节点级评论）
- 模板库（保存为模板）
- 发布页面（只读分享链接）

**前端改动**:
- 从 Canvas only → Canvas + Block Editor
- 需要协作编辑引擎（OT或CRDT）
- 权限系统UI

**商业模式**: SaaS（月费）+ 协作人数计费

---

### 路线 B: 专业分析工具（Tableau式）
**目标**: B2B企业战略分析工具

**关键特性**:
- 高级导出（PDF/PPT/JSON）
- 数据绑定（从数据库实时更新）
- 报告生成器（自动生成分析报告）
- API接口（第三方集成）
- 权限/审计（企业级）

**前端改动**:
- 导出引擎
- 报告编辑器
- 权限管理面板
- API文档

**商业模式**: SaaS（基础版/专业版/企业版）+ 数据量计费

---

### 路线 C: 协作设计工具（Figma式）
**目标**: 团队实时协作的无限Canvas

**关键特性**:
- 实时多人光标（谁在操作什么）
- 并发编辑（OT/CRDT同步）
- 版本历史（回滚到任何时刻）
- Team Workspace（项目/权限/成员）
- 评论&批注

**前端改动**:
- WebSocket改为OT/CRDT框架
- 增删改操作都需要同步到其他用户
- 版本面板UI
- Team管理UI

**商业模式**: SaaS 协作人数计费（Figma模式）

## 🎯 我的建议

**现在的"不够商业"症状：**
1. 缺少重复使用场景（用过一次就没了）
2. 缺少分享场景（只有你能看）
3. 缺少协作场景（无法团队工作）
4. 缺少变现场景（没有付费理由）

**最快的第一步**（不推翻重写）：
1. 加上**权限系统**（谁能访问）
2. 加上**分享链接**（只读预览）
3. 加上**导出功能**（PDF/图片）
4. 加上**模板库**（可复用的分析框架）

这样3-4周内可以达到"基础商业可用"。然后根据用户反馈选择上面哪条路线深耕。

## 🚨 必须回答的问题

在重设计前，你要清楚：

1. **你的用户是谁？**
   - 个人创业者？
   - 企业战略部？
   - 风投/咨询机构？
   - 教育机构？

2. **他们愿意付钱吗？**
   - 要多少钱才值？
   - 按人头？按月？按项目？

3. **他们最痛的问题是什么？**
   - 分析慢？
   - 团队协调难？
   - 方案评估复杂？
   - 知识管理混乱？

4. **你的独特优势在哪？**
   - 就是有AI吗？
   - 还是分析框架更好？
   - 还是用户体验更爽？

**回答不了这些，再好的UI也卖不出去。**
